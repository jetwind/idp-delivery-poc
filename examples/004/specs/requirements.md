# 需求规格
## 项目：一物一码追溯码管理服务

## 1. 背景与目标
企业需要为商品建立一物一码追溯体系。核心能力是：**按指定商品、批次、生产日期批量生成唯一追溯码**（码结构 = 企业前缀 + 商品代码 + 序列号，序列号按商品代码独立递增），并能**按追溯码查询**该产品对应的产品名、批次、生产日期。

- 后端：Java 21 + Spring Boot，提供 REST API。
- 前端：Vue，提供简单的追溯查询页面。
- 定位：原型/演示级。数据采用**内存态存储**（服务重启后清空），无需数据库。

**目标**：交付一个可运行的前后端一体的追溯码生成与查询服务，支撑批量赋码与按码溯源两类核心场景。

**关键确认**：
- 数据内存态存储，重启清空。
- 追溯码不加校验位，为纯顺序码。
- 序列号按商品代码独立计数（同一商品代码内严格唯一、递增）。
- 产品名、批次、生产日期在批量生成入参中直接传入。

## 2. 角色与场景（用户故事，含优先级）

| 角色 | 用户故事 | 价值 | 优先级 |
|------|---------|------|--------|
| 生产/库存管理人员 | 作为生产/库存管理人员，我希望选择商品、批次、生产日期并一次性批量生成多个唯一追溯码，以便快速为大批量产品赋码 | 提升赋码效率、避免手工逐个生成 | Must |
| 质检/售后人员 | 作为质检/售后人员，我希望输入任一追溯码即可查询对应的产品名、批次、生产日期，以便快速定位产品生产信息 | 支撑追溯、质量与售后处理 | Must |
| 消费者/前端使用者 | 作为查询页面使用者，我希望通过简单的 Vue 页面输入追溯码即可查看产品信息，以便无需技术背景也能自助完成查询 | 降低使用门槛 | Should |
| 后端开发者/运维 | 作为后端开发者/运维，我希望以标准 REST API 暴露批量生成与查询接口并保证同商品下序列号唯一，以便接口可被复用且并发生成不产生重复码 | 接口复用 + 数据唯一性 | Should |

## 3. 功能需求（逐条，含 Given/When/Then 验收标准）

### FR-1 按商品批量生成唯一追溯码
**描述**：后端提供批量生成接口，入参为企业前缀、商品代码、产品名、批次、生产日期、生成数量 N，对每一件产品生成唯一追溯码并入库（内存态）。追溯码结构 = 企业前缀 + 商品代码 + 序列号，序列号为纯顺序码（不加校验位），序列号按商品代码独立计数。

**验收标准**：
- Given 提交生成请求，When 入参包含企业前缀、商品代码、产品名、批次、生产日期及数量 N（1 ≤ N ≤ 1000），Then 返回 N 个追溯码且每个码结构 = 企业前缀 + 商品代码 + 序列号。
- Given 同一商品代码，When 分多次或并发生成，Then 序列号严格递增且在该商品代码下唯一，无重复码。
- Given 不同商品代码，When 各自动生成，Then 各自序列号独立从 1 开始计数互不干扰。
- Given 数量 N 非法（N<1、N>1000 或非数字），When 提交请求，Then 返回 400 参数校验错误。
- Given 必要入参缺失或为空，When 提交请求，Then 返回 400 参数校验错误。

### FR-2 按追溯码查询产品信息
**描述**：后端提供查询接口，入参为追溯码，返回该码对应的产品名、批次、生产日期。

**验收标准**：
- Given 一个已生成的追溯码，When 调用查询接口，Then 返回产品名、批次、生产日期且与生成时一致。
- Given 一个未生成/未入库的追溯码，When 调用查询接口，Then 返回 404（未找到）。
- Given 追溯码为空或格式非法，When 调用查询接口，Then 返回 400 参数校验错误。

### FR-3 Vue 前端查询页面
**描述**：提供简单页面，含追溯码输入框与查询按钮，通过后端 REST 查询接口展示产品名、批次、生产日期。（前端仅查询，不提供生成 UI。）

**验收标准**：
- Given 用户输入追溯码并点击查询，When 码存在，Then 页面展示产品名、批次、生产日期。
- Given 用户输入追溯码并点击查询，When 码不存在，Then 页面给出明确的未找到提示。
- Given 追溯码输入为空，When 点击查询，Then 页面阻止提交并提示「请输入追溯码」。

## 4. 非功能需求
1. **性能**：批量生成接口单次支持 N ≤ 1000，响应在合理时间（毫秒到秒级）内返回。
2. **并发**：并发生成请求下，同一商品代码内序列号必须严格唯一、递增，不允许出现重复码；需采用线程安全的序列号分配机制。
3. **可用性**：API 返回规范化错误码与消息（400/404 等），便于前端与调用方处理。
4. **技术栈约束**：后端 Java 21 + Spring Boot，前端 Vue。
5. **可维护性**：码生成逻辑与查询逻辑分离，序列号规则集中配置。
6. **数据一致性**：内存态存储，查询到的产品信息与生成时保持一致。

## 5. 范围外与约束
**范围外**：
- 数据库持久化与历史数据留存（当前仅内存态，服务重启后数据清空）。
- 追溯码校验位/校验算法（如 GS1 Luhn），当前为纯顺序码。
- 二维码/DataMatrix 码的生成与扫码解析。
- 码生命周期管理（激活/出库/销售/失效）与状态流转。
- 箱码/垛码等层级关联。
- 防伪、防窜货、区域绑定及营销功能。
- 身份认证、权限管理与用户登录。
- 批量导入/导出文件及报表。
- 商品档案/前缀的独立后台管理（产品名由生成入参直接提供）。
- 前端批量生成 UI（前端仅查询）。

**约束**：
- 技术栈固定为 Java 21 + Spring Boot（后端）与 Vue（前端）。
- 追溯码结构固定为「企业前缀 + 商品代码 + 序列号」，序列号为顺序码，不加校验位。
- 序列号按商品代码独立计数。

## 6. 风险与待确认问题
**风险**：
- 内存态存储导致重启后数据丢失，不适合生产环境，仅限原型/演示。
- 顺序号模式容易被预测，若未来需要防伪需引入随机序列号或校验位。
- 若序列号分配未做线程安全处理，并发下同一商品代码可能产生重复码。

**待确认问题**：
- 后续如需生产化，需引入数据库持久化、身份认证与多租户隔离，并可在设计阶段进一步确认接口契约。
