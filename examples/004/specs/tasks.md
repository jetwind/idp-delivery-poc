# 任务拆解

项目：一物一码追溯码管理服务
阶段：03 任务
输入：specs/requirements.md（已定稿）、docs/design.md（已定稿）
拆分原则：INVEST（Independent / Negotiable / Valuable / Estimable / Small / Testable）

> 关键设计基线（任务拆分的依据，来自详细设计）：
> - 追溯码段长集中配置：企业前缀 3 位、商品代码 3 位、序列号 8 位（高位补零），总长 14 位纯数字，无分隔符、无校验位。
> - 序列号按 (企业前缀, 商品代码) 独立从 1 递增，分片 ReentrantLock + AtomicLong 原子预留区间，保证并发无重复码。
> - 数据内存态存储（ConcurrentHashMap），服务重启清空，原型/演示定位。
> - 后端按层分包：controller / service（ApplicationService、Generator、QueryService）/ store / config / model + 全局异常。
> - 前端仅查询（FR-3），不提供生成 UI。

## 1. 服务清单（服务名 → 新建/升级 + 技术栈）

| 服务名 | 类型 | 技术栈 | 说明 |
|--------|------|--------|------|
| trace-code-service | 新建服务 | 后端：Java 21 + Spring Boot 3.2.x + Maven（spring-boot-starter-web、starter-validation），内存态存储 | 提供批量生成与按码查询 REST API，序列号分配线程安全，段长集中配置 |

## 2. 任务列表（每个任务：ID、标题、服务归属、INVEST 评估、验收标准、依赖任务、估算）

### T1 搭建后端工程骨架与基础设施
- **服务归属**：trace-code-service（新建服务）
- **INVEST 评估**：I-工程骨架是后端唯一地基，第 1 环独占、无并行冲突；N-包名、端口、健康端点形式可协商；V-奠定全部后端模块的编译、运行与统一响应/异常基础设施；E-约 1 人日；S-仅工程+配置+基础设施，不含业务逻辑；T-以「可启动 + 配置生效 + 统一响应/异常链路可验证」验收。
- **验收标准**：
  1. `mvn spring-boot:run` 可启动，Java 21 编译通过，默认端口 8080，无报错退出。
  2. `TraceCodeProperties` 绑定集中配置 `trace-code.prefix-length=3 / product-code-length=3 / serial-number-length=8`，并提供只读派生能力（如总长 14、序列号容量上限），无散落硬编码。
  3. `ApiResponse<T>{code,message,data}` 统一响应体、`ErrorCode` 错误码枚举、`TraceCodeFormatException`（映射 400）、`TraceCodeNotFoundException`（映射 404）定义完备。
  4. `GlobalExceptionHandler`（@RestControllerAdvice）已挂载：格式/校验异常 → 400、未找到 → 404、其它异常 → 500，响应体均为统一 ApiResponse 格式。
  5. 提供探测端点（如 `GET /api/v1/ping`）返回统一成功响应，验证「请求 → Controller → 统一响应」链路可用。
- **依赖任务**：无
- **估算**：1 人日

### T2 实现内存态存储与领域模型
- **服务归属**：trace-code-service（新建服务）
- **INVEST 评估**：I-第 2 环内与 T3 互不依赖可并行；N-存储内部组织（单 Map vs Map+计数）可协商；V-提供按追溯码索引的内存存储底座，是查询与一致性的数据基础；E-约 0.5 人日；S-一个领域对象 + 一个存储类；T-单元测试覆盖存取一致与线程安全。
- **验收标准**：
  1. `ProductRecord` 领域对象含 traceCode / companyPrefix / productCode / productName / batchNo / productionDate 六个字段，与详细设计一致。
  2. `InMemoryTraceCodeStore` 基于线程安全 Map 实现，提供 `save(traceCode, record)` 与 `findByTraceCode(traceCode)`（未命中返回 empty）。
  3. 单元测试：保存后可按码查回且字段与生成时一致；未保存的码返回空；并发写入不同码不丢失数据。
- **依赖任务**：T1
- **估算**：0.5 人日

### T3 实现序列号分配器与追溯码生成器
- **服务归属**：trace-code-service（新建服务）
- **INVEST 评估**：I-第 2 环内与 T2 互不依赖可并行；N-分片锁对象（CounterLock）内部字段组织、异常类型可协商；V-实现码组装与序列号唯一递增这两条核心业务规则（R1/R2/R4/R8）的唯一代码处；E-约 1 人日；S-仅生成器与分配器，不含用例编排；T-单元测试覆盖递增、补零、跨商品独立、容量溢出。
- **验收标准**：
  1. `generate(companyPrefix, productCode, startSerial, count)` 返回 count 个 `TraceCodeItem`，traceCode = 3 位前缀 + 3 位商品码 + 8 位补零序列号，总长 14 位纯数字。
  2. 序列号从 startSerial 起连续递增，1 格式化为 `00000001`（高位补零 8 位）。
  3. 段长全部读自 `TraceCodeProperties`，代码中无散落硬编码。
  4. 单元测试：连续生成、补零格式、跨商品序列号独立、序列号超出 8 位容量时抛业务异常（防溢出，不产生非法码）。
- **依赖任务**：T1
- **估算**：1 人日

### T4 实现生成用例编排服务
- **服务归属**：trace-code-service（新建服务）
- **INVEST 评估**：I-第 3 环内与 T5 互不依赖可并行；N-兜底校验策略与分片锁创建/复用细节可协商；V-支撑 FR-1 批量生成核心用例（含多次追加与并发唯一）；E-约 1 人日；S-一个编排方法 + 并发控制，无新领域逻辑；T-单测 + 并发单测可验证。
- **验收标准**：
  1. `generateTraceCodes(req)` 以 (companyPrefix, productCode) 为粒度原子预留连续序列区间 [next, next+count)，委托 T3 的 Generator 组装后写入 T2 的 Store，返回码列表。
  2. 同一商品代码多次生成：序列号严格递增、追加不覆盖旧记录（旧码仍可查询，R5）。
  3. 并发单测：多线程并发对同一商品生成，码总数正确、序列号集合无重复（R4）。
  4. 不同商品代码各自从 1 独立计数、互不干扰（R3）。
  5. 兜底校验：N<1 / N>1000 / 必要入参缺失或为空 → 抛参数校验异常（映射 400）。
- **依赖任务**：T2、T3
- **估算**：1 人日

### T5 实现按码查询服务
- **服务归属**：trace-code-service（新建服务）
- **INVEST 评估**：I-第 3 环内与 T4 互不依赖可并行；N-内部三元组解析结构、异常消息文案可协商；V-支撑 FR-2 按码溯源用例；E-约 0.5 人日；S-格式校验 + 定长解析 + 查库一个方法；T-单测覆盖命中/未命中/格式非法/空全部分支。
- **验收标准**：
  1. 空码、含非数字字符、总长非 14、无法按定长规则切分 → 抛 `TraceCodeFormatException`（映射 400）。
  2. 格式合法但未入库 → 抛 `TraceCodeNotFoundException`（映射 404）。
  3. 命中 → 返回 productName / batchNo / productionDate，且与生成时一致（R6）。
  4. 单元测试覆盖上述全部分支（R7）。
- **依赖任务**：T2
- **估算**：0.5 人日

### T6 实现 REST 接口层
- **服务归属**：trace-code-service（新建服务）
- **INVEST 评估**：I-第 4 环独占（依赖 T4/T5 完成后即可独立实施）；N-错误码枚举取值、HTTP 状态码语义可协商；V-将生成与查询两个用例暴露为标准、可复用的 REST API，是前后端联调契约；E-约 1 人日；S-一个 Controller 两个端点 + 集成测试；T-集成测试全覆盖 200/400/404 与并发无重复。
- **验收标准**：
  1. `POST /api/v1/trace-codes`：jakarta validation + 格式校验（N∈[1,1000]、必填非空、前缀/商品码纯数字且定长、生产日期合法）；成功 200 返回 `ApiResponse<TraceCodeGenResponse>`（含 N 个码及结构化三元组）；非法入参 → 400。
  2. `GET /api/v1/trace-codes/{code}`：成功 200 返回产品三元组；空/格式非法 → 400；未入库 → 404。
  3. MockMvc/@SpringBootTest 集成测试覆盖：生成成功、N 非法 400、字段缺失 400、查询 200/400/404。
  4. 集成级并发验证：并发 POST 同一商品返回的码无重复、序列号递增。
- **依赖任务**：T4、T5
- **估算**：1 人日

### T7 搭建前端工程并实现查询页面
- **服务归属**：trace-query-web（新建服务）
- **INVEST 评估**：I-第 5 环独占；N-UI 布局样式、请求实现（fetch 细节）、环境变量命名可协商；V-支撑 FR-3 消费者自助查询，让非技术用户可用；E-约 1~2 人日；S-单页面 + 单组件；T-三场景手工验收（空输入 / 命中 / 未找到 / 服务异常）可复现。
- **验收标准**：
  1. `npm run dev` 可启动，页面含追溯码输入框与查询按钮。
  2. 空输入点击查询：阻止请求并提示「请输入追溯码」。
  3. 码存在：页面展示产品名、批次、生产日期。
  4. 码不存在：页面给出明确的未找到提示（404 分支）。
  5. 服务异常（非 200/404）：展示错误信息。
  6. 与后端联调通过（Vite 开发代理或后端 CORS 放行前端源，解决跨域）。
- **依赖任务**：T6
- **估算**：1~2 人日

### T8 健壮性收尾与运行文档
- **服务归属**：trace-code-service（新建服务；文档覆盖前后端两服务）
- **INVEST 评估**：I-第 6 环独占（主体功能已交付）；N-边界测试清单、README 结构可协商；V-补强边界与并发可信度、交付可复现的运行说明；E-约 1 人日；S-边界测试 + README，无新功能；T-边界测试全绿、README 步骤可复现。
- **验收标准**：
  1. 边界测试：N=1、N=1000 成功生成；N=0、N=1001、N 非数字 → 400，均通过。
  2. 并发与独立性测试：并发同商品无重复码；跨商品序列号独立计数。
  3. 序列号容量溢出防御：预留前校验，超出 8 位容量返回明确业务错误，不产生非法码。
  4. README：前后端启动步骤、REST API 说明、内存态风险声明（重启清空）、段长集中配置说明（3/3/8、总长 14）。
- **依赖任务**：T6、T7
- **估算**：1 人日

## 3. 依赖关系（文本描述）

- **T2、T3 → T1**：后端所有模块须在工程骨架（Java 21 + Spring Boot 编译环境、`TraceCodeProperties` 段长配置、统一响应/异常基础设施）之上开发，否则无法编译与注入配置。
- **T4 → T2、T3**：生成用例编排需要 T2 的内存存储（写入记录）与 T3 的码生成器（组装码/分配序列号）。
- **T5 → T2**：按码查询服务需要 T2 的内存存储（按码检索）与领域模型。
- **T6 → T4、T5**：REST 控制器同时编排生成（T4）与查询（T5）两个用例，二者就绪后接口层才能完整交付。
- **T7 → T6**：前端查询页依赖后端查询接口作为联调契约，需 T6 完成后方可端到端验收。
- **T8 → T6、T7**：边界/并发测试面向完整 REST API（T6），README 需覆盖后端（T6）与前端（T7）两服务的运行说明。

无其它跨任务依赖。同一环内任务之间无依赖，可并行派发。

## 4. 任务环编排（第 1 环可并行任务 / 第 2 环 / ...）

| 环 | 可并行任务 | 说明 |
|----|-----------|------|
| 第 1 环 | T1 | 后端工程骨架与基础设施（唯一地基，独占） |
| 第 2 环 | T2、T3 | 存储与领域模型 / 序列号分配器与码生成器 —— 互不依赖可并行 |
| 第 3 环 | T4、T5 | 生成用例编排 / 按码查询服务 —— 互不依赖可并行 |
| 第 4 环 | T6 | REST 接口层（生成 + 查询端点，整合 T4/T5） |
| 第 5 环 | T7 | Vue 前端查询页（依赖后端查询接口联调） |
| 第 6 环 | T8 | 健壮性收尾（边界/并发测试、容量防御、README） |

- 环与环之间串行：第 N 环的全部任务完成后，方可开始第 N+1 环。
- 环内并行粒度即一次可派发给多个子代理的工作量（第 2、3 环各 2 个任务可并行）。
- 执行节奏与详细设计第 6 节对齐：第 1~4 环 ≈ P0（核心可运行后端），第 5 环 ≈ P1（端到端可用），第 6 环 ≈ P2（健壮性收尾）。
